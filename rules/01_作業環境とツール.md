# 01 作業環境とツール

[INDEX](KiCad_MCP_ルール.md)

## ルール

1. **作業はローカルの作業フォルダ `C:\Users\<user>\Documents\KiCad_work` で行い、完成したものだけ OneDrive のプロジェクト `C:\Users\<user>\OneDrive\KiCad\Project\<名前>` へコピーする。** OneDrive 上のファイルを直接編集しない。
2. **作業を始める前に、OneDrive 側とローカル側のファイルを比較し、新しい方を元にする**（ユーザーが KiCad で手を加えていることがある）。
3. **変更の前に必ずバックアップを取る。** OneDrive 側は `old_<内容>\` フォルダか `*.bak` で残す。回路図は変更ごとにスナップショットを残す。
4. 最初は読み取り（情報取得・ERC・DRC）から始め、**変更は計画を示してから**行う。
5. MCP の一括操作は小さく分け、1 回ごとに保存を確認する。MCP が不安定になったら固執せず、`kicad-cli` と KiCad 付属 Python の自作スクリプトに切り替える。
6. 回路図はファイルを直接編集する（MCP の回路図 IPC は未対応）。ERC・DRC・出力は `kicad-cli` で行う。
7. パスは絶対パスで `/` 区切り、寸法は mm で書く。
8. 長い処理はバックグラウンドで実行し、ログの完了行を待つ。複数案を並行実行してよい（CPU 6 コア）。
9. **プロセスを止めるときは、コマンドラインで対象を特定して PID で止める。** `taskkill /IM python.exe` は使わない。
10. ファイルのダウンロード（データシートを含む）は、ファイル名・取得元・サイズを示して**ユーザーの許可を得てから**行う。
11. MCP の `register_*_library` は `project` スコープで使う（`global` は使わない）。
12. **並行して動かすスクリプトが同じ `.kicad_pcb` を読むときは、実行ごとにコピーを読ませる**（KiCad のロックファイルを取り合う）。

### プロセスの止め方（PowerShell）

```powershell
Get-CimInstance Win32_Process -Filter "name='python.exe'" | ForEach-Object { "{0} {1}" -f $_.ProcessId, $_.CommandLine }
Stop-Process -Id <PID> -Force
```

### トラブルシューティング

| 症状 | 対処 |
|---|---|
| サーバが表示されない | セッションを再起動。`node -v` で Node.js を確認 |
| pcbnew の import エラー | `KICAD_PYTHON` と `PYTHONPATH` が KiCad 10.0 を指しているか確認 |
| MCP の Python が止まった | `kicad-cli` と自作スクリプトに切り替える |
| 回路図が読めない | KiCad 10 形式（`20260101`）対応の版か確認し、サーバを更新 |
| DRC・出力が失敗 | `kicad-cli version` が通るか確認 |

サーバの更新: `cd C:\Users\<user>\Documents\KiCAD-MCP-Server` → `git pull` → `npm install` → `npm run build`。

### シェル・Python の書き方

- シェルの `rm` でワイルドカードを使わない（新しい出力フォルダを切るか、ファイルを個別に指定）。
- Python の heredoc にバックスラッシュ（`\n`、`\r`、パス）を書かない。`chr(10)`・`chr(92)` を使うか、ファイルに書いてから実行する。
- pcbnew の `FromMM()` には `float()` で変換した値を渡す（numpy の数値は受け付けない）。
- pcbnew で同じ反復の中で `Remove()` を繰り返すと SWIG のエラーになる。消す対象を先にリストにし、消したら保存して読み直す。

## 理由（過去の失敗）

- 12: 6 つの計算が同じ基板を `LoadBoard` して、`~*.kicad_pro.lck couldn't be removed (error 32)` の画面が出て 1 つが止まった（2026-10-18）。

- 1: OneDrive 同期中の `.kicad_sch` が 0 バイトになった。
- 2: ユーザーが 2 枚の面付けや手動配線をしていたのに気付かず、古い基板を元にしかけた。
- 5: MCP のバッチ呼び出しが 30 秒を超えてタイムアウトし、回路図が途中までしか書かれない／空になった。MCP の Python が応答しなくなったこともある。
- 9: `taskkill /IM python.exe` で KiCad MCP サーバのプロセスまで止まった。
- 10: データシートの PDF がブラウザでダウンロード扱いになり、保存ダイアログが出た。
- 11: `global` で登録しても、Claude のアプリ領域に振り替えられた別の設定に書かれ、本物の KiCad に反映されなかった。
- 修正済みの基板を pcbnew で読み直して同じスクリプトを再実行すると SWIG エラーが出た（→ 基板は毎回ネットリストから新規生成。既存基板の再利用は部品位置の読み込みに限る。[08_スクリプト一覧](08_スクリプト一覧.md)）。
